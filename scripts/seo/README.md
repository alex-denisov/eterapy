# SEO / GEO / AEO toolkit

Инструменты, которых нет ни в одном нашем MCP: индексация вне Яндекса,
регрессия поисковой разметки между выкатками, бесплатные беклинки, полевые
Core Web Vitals, первоисточник по апдейтам Google.

**Это не плагин и не скилл.** Обычные CLI на Python плюс один shell-вход.
Любой агент — Claude Code, Codex, OpenCode, Gemini — и человек запускают одну
и ту же команду. Каталог самодостаточен: скопируй или слинкуй `scripts/seo/`
в другой репозиторий, и он работает там без правок — ни имя проекта, ни домен,
ни пути наружу не зашиты. Настройки проекта живут в `seo.env`, состояние —
в `.state/`, оба вне git.

## Установка

```bash
scripts/seo/seo setup            # venv + requests/bs4/lxml
cp scripts/seo/seo.env.example scripts/seo/seo.env   # заполнить
scripts/seo/seo doctor           # что подключено, чего не хватает
```

Search Console требует дополнительных пакетов: `scripts/seo/seo setup --google`.

`scripts/seo/seo list` печатает актуальный список инструментов, у каждого есть
`--help`. Большинство умеет `--json` — им и пользуйся при машинной обработке.

## Что чем решается

### Индексация за пределами Яндекса

Мы сидим на одном поисковике. Это не только риск, это потолок трафика.

| Инструмент | Зачем | Что нужно |
|---|---|---|
| `indexnow-submit` | мгновенная отправка URL в Яндекс, Bing, Seznam, Naver одним вызовом | ключ генерируешь сам, аккаунта нет |
| `sitemap-discovery` | найти и разобрать карты сайта, включая индексные | ничего |
| `gsc-query` | запросы, показы, позиции по нашему сайту в Google | доступ владельца в Search Console |
| `gsc-inspect` | настоящий статус индексации конкретного URL | то же |
| `bing-webmaster` | индексация и запросы в Bing | бесплатный ключ |

IndexNow — самый быстрый способ расширить охват: ключ это 32 hex-символа,
файл с ключом лежит в статике, дальше отправляем адреса пачками. Он же снимает
нагрузку с квоты переобхода Вебмастера (150 URL/сутки).

### Регрессия поисковой разметки

`drift-baseline` снимает слепок (title, description, canonical, robots, h1,
структура заголовков, число блоков schema, статус, редиректы), `drift-compare`
сверяет живую страницу с ним по 17 правилам, `drift-history` и `drift-report`
показывают динамику.

Это прямой ответ на два наших инцидента: soft-404 из-за корневого `loading.tsx`
и обвал пререндера с 219 адресов до 14 из-за чтения кук в корневом layout.
Оба меняли ровно те поля, которые снимает baseline, и оба мы заметили поздно.

```bash
scripts/seo/seo drift-baseline --skip-cwv https://eterapy.com/pricing
# …выкатка…
scripts/seo/seo drift-compare https://eterapy.com/pricing
```

База — `scripts/seo/.state/drift/baselines.db`, своя у каждого проекта.
`SEO_DRIFT_DB` переопределяет путь.

### Скорость по полевым данным

`pagespeed-check`, `crux-history`, `lcp-subparts` — это данные реальных
пользователей Chrome, а не лабораторный прогон. `lcp-subparts` раскладывает LCP
на TTFB, задержку загрузки, саму загрузку и отрисовку, то есть говорит, что
чинить. chrome-devtools MCP такого не даёт — он лабораторный.

### Беклинки без Ahrefs

`commoncrawl-graph` читает открытый веб-граф Common Crawl: ранг домена и
гармоническая центральность бесплатно. Слабее платных сервисов, но у нас в этой
графе сейчас ноль. Первый запуск по домену качает крупный индекс релиза, кэш
общий — `~/.cache/claude-seo/commoncrawl`.

### Контент и GEO

`content-quality` — оценка по критериям асессорских рекомендаций Google:
доля воды, узнаваемые ИИ-обороты, плотность информации, повторы.
`content-verify` — ищет утверждения без источника. Оба работают со stdin, оба
на голой стандартной библиотеке.

Скармливай **текст, а не HTML**: разметка накручивает счётчик повторов.

`seo-updates` — датированный первоисточник по апдейтам Google со ссылками.
Полезен ровно тем, что убирает догадки. Две вещи оттуда, которые меняют нашу
работу над GEO/AEO:

- Google официально заявил, что оптимизация под генеративные ответы — **это
  обычное SEO**: не нужны отдельные файлы, отдельная разметка, чанкинг или
  переписывание под ИИ. **`llms.txt` поиск Google игнорирует.**
- В Search Console появился отчёт по AI Overviews и AI Mode. Это единственный
  первоисточник, по которому мы вообще сможем измерить AEO-видимость.

Второй пункт — практический аргумент за подключение GSC: без него мы про
цитируемость в ИИ-ответах не знаем ничего.

## Чего мы намеренно не берём

**GA4 и любой экспорт аналитики в Google — вне периметра.** Данные о поведении
пользователей остаются в Метрике. В этом каталоге нет `ga4_report` и не будет.
Всё, что здесь есть, отправляет наружу только адреса наших собственных страниц
и читает данные о нашем же сайте — это не передача пользовательских данных.

Не взято также: `keyword_planner` (нужен доступ к Google Ads), `moz_api`,
`dataforseo_*`, `render_page` (у нас для этого есть Playwright и
chrome-devtools MCP), генераторы schema (JSON-LD у нас уже свой), и весь пласт
скиллов про Google Business Profile, Amazon и локальное SEO — к нам неприменим.
Подбор ключевых слов под RU остаётся за Wordstat MCP, он для нашего рынка лучше.

## Порядок действий, если нужен трафик и выручка

1. **IndexNow** — ключ, файл в статике, отправка всех индексируемых адресов.
   Полдня работы, немедленно расширяет охват за пределы Яндекса.
2. **Search Console** — доступ владельца, потом `gsc-inspect` по всем адресам
   каталога. Мы до сих пор не знаем, что Google реально проиндексировал.
3. **Drift-базлайны** по ключевым публичным страницам, сверка после каждой
   выкатки. Это защита от повторения двух уже случившихся обвалов.
4. **Полевые CWV** по посадочным, `lcp-subparts` для приоритизации.
5. **Content-quality** в контентный маршрут B578 как редакционный порог.

## Известные упоры

**CrUX отвечает 403 `API_KEY_SERVICE_BLOCKED`.** Ключ рабочий (PageSpeed на нём
отвечает), но в проекте Google Cloud не включён Chrome UX Report API. Лечится
в консоли: APIs & Services → Enable APIs → *Chrome UX Report API*. Касается
`crux-history` и `lcp-subparts`; `pagespeed-check` работает и без него.

**OAuth не запускается второй раз.** Флоу поднимает локальный сервер на порту
8085 и ждёт редиректа из браузера. Брошенный запуск держит порт дальше, и
следующий падает. `seo` это проверяет заранее и печатает, кого убить.

**Сертификаты.** Часть инструментов ходит через stdlib `urllib`, у которого на
сборках python.org для macOS пустое хранилище корневых сертификатов — падает
`CERTIFICATE_VERIFY_FAILED`, в том числе при обмене OAuth-кода на токен. `seo`
подставляет бандл certifi в `SSL_CERT_FILE`, так что запускать инструменты
надо через него, а не `python3 script.py` напрямую.

## Происхождение и ресинк

Скрипты взяты из [AgriciDaniel/claude-seo](https://github.com/AgriciDaniel/claude-seo)
(MIT, см. `LICENSE.upstream`), версия 2.2.4. Плоская раскладка сохранена
специально: апстрим кладёт всё в один каталог и импортирует соседей, поэтому
файл можно обновить копированием поверх.

Два файла разошлись с апстримом осознанно:

- `drift_baseline.py` — база вынесена в проект вместо общего `~/.cache`,
  иначе два проекта делят одну историю;
- `seo_updates.py` — данные ищутся рядом со скриптом, потом по-апстримовому.

Плагин целиком не ставим сознательно: 25 скиллов и 18 агентов добавляют около
3700 токенов в системный промпт **каждой** сессии, а уникальной ценности в них
на пять инструментов, которые здесь и лежат.
